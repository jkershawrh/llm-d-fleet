llm-d-fleet
granular technical reference

What every major component does, why it exists, what it consumes and emits, where its authority ends, and how requests and state move through the fleet.

Core invariant: compatibility, authorization, policy, freshness, and health constrain the candidate set before any balancing or data-plane optimization occurs. An adapter may translate that set; it may never expand it.

End-to-end event-flow diagram

Solid paths are live request execution; dashed paths are asynchronous state and observations; red is an explicit failure response.

Architectural flow

The request plane is stateless and horizontally scalable. The leader-elected control plane maintains the provider state it consumes; optional governance and observability remain outside the inference hot path.

Inference request: step by step

Open any stage for its purpose and failure behavior. This is the supported client-to-model path.

Public ingressModel/API Gateway
What happensTerminates public TLS, authenticates the caller, resolves the tenant and signs a short-lived normalized identity assertion.
WhyFleet consumes trusted identity but does not duplicate an enterprise IdP, MFA, subscription or API-key lifecycle.
Failure behaviorInvalid identity never reaches fleet; gateway returns its authentication error.
Trust verificationFleet inference gateway
What happensVerifies assertion signature, issuer, audience, time window and verified proxy transport context.
WhyA caller-supplied identity header is not trustworthy without cryptographic and transport binding.
Failure behaviorReturn 401/403 and record an authentication or RBAC denial.
Header sanitizationFleet inference gateway
What happensRemoves caller-provided cluster, destination, authority, data-plane, routing and internal identity headers.
WhyOnly fleet policy may address Praxis, Router or a spoke inference endpoint.
Failure behaviorSpoofed values are ignored or rejected; they cannot affect selection.
Request admissionFleet inference gateway
What happensApplies body-size, rate, active-concurrency and timeout bounds before expensive processing.
WhyProtects shared control and inference capacity from malformed or unbounded work.
Failure behaviorReturn structured 429 or request-size error without reserving backend capacity.
Tenant policyQuota and authorization services
What happensChecks role, tenant profile, model entitlement, cluster restrictions, token estimate and live usage.
WhyAuthentication identifies a caller; tenant policy determines what that caller may consume.
Failure behaviorFail closed with a structured quota or policy denial.
Model resolutionClassifier + exact-model map
What happensUses the explicit request and optional semantic classification to resolve one logical request to one exact physical model.
WhyA cheaper fallback is not equivalent when weights, version, precision or behavior change.
Failure behaviorIf no authorized exact model exists, return 503 no_compatible_capacity.
Provider qualificationFleet eligibility policy
What happensIntersects model compatibility, tenant policy, placement, freshness, draining state, health, capacity and failure-domain requirements.
WhyOptimization is safe only after every hard constraint has removed ineligible providers.
Failure behaviorAn empty intersection returns 503; an adapter may not restore excluded providers.
Fleet selectionSession + FleetRoutingPolicy
What happensApplies valid session affinity, escalation rules, policy weights, latency or connection strategy to the qualified set.
WhySelection behavior is configurable while the safety envelope remains invariant.
Failure behaviorStale or incompatible affinity is discarded and selection is recomputed.
Quota reservationTenant quota service
What happensAtomically reserves active request and estimated token capacity for the selected model/provider.
WhyConcurrent requests must not all pass against the same pre-request usage snapshot.
Failure behaviorReservation failure returns 429 and no upstream request is sent.
Data-plane handoffInferenceProvider boundary
What happensChooses the operator-configured Praxis or llm-d Router target and rewrites the request to the exact physical model.
WhyData-plane choice is a deployment concern, never a client routing control.
Failure behaviorMissing target, credentials or trust configuration fails closed.
Endpoint routingPraxis or Router/EPP
What happensRoutes only inside the fleet-qualified provider representation; EPP may optimize cluster-local queue, KV, prefix or session behavior.
WhyFleet owns cross-cluster eligibility while the data plane owns efficient transport and local endpoint choice.
Failure behaviorEPP or routing failure cannot bypass fleet because failure_mode_allow is false.
Cross-cluster transportTLS streaming proxy
What happensSets trusted authority/SNI, verifies the backend certificate, attaches operator credentials and streams request and response with cancellation.
WhyCross-cluster traffic needs identity, confidentiality, bounded retries and backpressure.
Failure behaviorRetry only before response headers; never retry an in-progress streamed generation.
Model executionKServe/InferencePool model server
What happensExecutes the exact model on the selected CPU or GPU provider and emits tokens plus execution metadata.
WhyCluster-local serving systems own pod lifecycle, revisions, readiness and accelerator utilization.
Failure behaviorBackend status and streaming semantics are preserved through the gateway.
Response verificationFleet inference gateway
What happensChecks execution identity where supported and returns request ID, selected cluster/model, routing reason and data-plane metadata.
WhyThe decision and actual execution must be correlatable and wrong-model execution detectable.
Failure behaviorIdentity mismatch is evidence of a routing contract violation, not a successful request.
Accounting and evidenceFleet metrics, metering and optional ledger
What happensReleases concurrency, records tokens/latency/outcome without prompts, emits metrics/events and optionally records immutable evidence.
WhyOperations, quota and audit need reconstructable outcomes without exposing user content.
Failure behaviorOptional telemetry degrades independently; a configured governed ledger fails closed by profile contract.

Compact event-flow reference

Inference request

  1. External gateway authenticates caller and signs normalized identity
  2. Fleet strips internal headers; enforces body, concurrency, auth, role, and rate controls
  3. Resolve explicit/semantic logical request to one exact physical model
  4. Filter registered providers by exact model, policy, freshness, draining, health, and capacity
  5. Apply session and fleet routing policy; reserve tenant quota
  6. Select operator-configured Praxis or Router forwarding target
  7. Proxy streaming request with request ID; retry CPU only before response headers
  8. Verify Router execution identity when applicable; preserve backend status/stream
  9. Return routing/model metadata; release quota; emit metrics and optional evidence

Desired-state reconciliation

  1. Kubernetes watch observes FleetInferencePool or policy change
  2. Leader-owned reconciler loads durable pool and cluster state
  3. Constraint solver removes infeasible clusters
  4. Scorer ranks remaining placement candidates
  5. Selected serving target receives desired placement
  6. InferencePool path preserves existing lifecycle; KServe path server-side applies LLMInferenceService
  7. Current-generation readiness/address is ingested
  8. Normalized qualified provider set is recalculated
  9. Exactly one routing adapter publishes its representation atomically
  10. Observed state, events, metrics, and optional ledger evidence are updated

Provider failure

  1. SWIM/Grid state, agent freshness, or active HTTPS probe detects loss
  2. Provider health moves to unavailable after bounded failure threshold
  3. Fleet removes it from the exact-model eligible set
  4. Adapter publishes withdrawal; Router mirror observes an atomic tombstone/snapshot
  5. New CPU requests select another compatible failure domain
  6. If sole GPU provider is lost, exact GPU requests return 503 no_compatible_capacity
  7. In-progress streamed generations are never retried after bytes/headers
  8. Provider returns only after consecutive successful checks and current capability evidence

Optional governed intent

  1. DeepField may publish an observation outside the request path
  2. GCL may formulate and Ed25519-sign an expiry/scope-bounded DecisionPackage
  3. Fleet verifies authorship, expiry, scope, algorithm policy, identity, and fleet authorization
  4. FleetIntent and FleetOperation record proposal and execution lifecycle
  5. Leader actuates only the authorized bounded change
  6. External immutable ledger records evidence and returns a receipt
  7. Receipt proves recording but cannot authorize any action
  8. Configured ledger failure fails closed in the governed profile
